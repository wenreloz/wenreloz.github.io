Fast Is a Feeling: Better Loading UX in Angular 22.

How to make an Angular 22 interface feel faster by designing the moments before its content is ready.

Performance is measured in milliseconds, but experienced as confidence. A page can finish loading quickly and still feel slow if it begins blank, flashes several states, or shifts just as someone tries to interact. Good loading UX gives every moment a clear purpose.

Angular 22’s @defer block connects a performance decision directly to the template. Components, directives, pipes, and their CSS inside the block can be split into separate chunks and loaded when needed. The interesting UI/UX work begins with choosing when that should happen: during browser idle time, as content approaches the viewport, or after deliberate interaction.

A placeholder should preserve the shape of the content that will replace it. Matching the approximate height and structure prevents cumulative layout shift—the frustrating movement that can make a person lose their reading position or click the wrong control. A skeleton is useful when it communicates structure; a generic spinner often communicates only delay.

@defer (on viewport; prefetch on idle) {
  <app-insights-panel />
} @placeholder {
  <app-insights-skeleton aria-hidden="true" />
} @loading (after 150ms; minimum 400ms) {
  <p role="status">Loading insights…</p>
} @error {
  <p role="alert">Insights could not be loaded.</p>
}

The loading state also needs restraint. Angular lets @loading wait before appearing and remain for a minimum duration. A short delay prevents a spinner from flashing for work that completes almost immediately, while a minimum display time prevents visual flicker once it does appear. Both choices should support continuity instead of making the interface seem busier.

Every deferred region needs a failure state as well. An error message should explain what failed and offer a recovery action when retrying is possible. Accessibility belongs in these transitions: status text should be announced without stealing focus, decorative skeletons should stay out of the accessibility tree, and controls should remain usable with a keyboard.

The most important content should still arrive first. Deferring a hero, primary form, or information already visible above the fold can make the page less stable and hurt the very performance metrics the feature is meant to improve. @defer works best for heavy, secondary, or below-the-fold experiences.

Angular 22 also makes OnPush the default component change-detection strategy, reducing unnecessary checks by default. For server-rendered applications, incremental hydration is enabled through provideClientHydration without the older withIncrementalHydration opt-in. These defaults support responsive interfaces, but profiling with Angular and browser developer tools should still guide optimization.

The strongest Angular loading experience is not the one with the most animation. It is the one that preserves context, avoids surprise, communicates honestly, and lets people continue with confidence. Real speed matters. The way waiting feels matters too.
