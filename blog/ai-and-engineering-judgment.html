Using AI Without Giving Up Engineering Judgment.

How I use AI to move faster while keeping responsibility for technical decisions and results.

AI is useful when it shortens the distance between a question and something I can evaluate. I use it to explore approaches, clarify unfamiliar concepts, draft repetitive code, and identify cases I may want to test.

The useful part is not accepting the first output. It is reviewing the assumptions, checking the code against the system around it, and deciding whether the result is appropriate for the actual requirement.

That review matters most in enterprise and healthcare software. Correctness, privacy, maintainability, and clear behavior still belong to the engineer. Generated code needs the same scrutiny as any other contribution.

I treat AI as one tool in the development workflow. It can accelerate exploration and execution, while engineering judgment determines what should reach production.
